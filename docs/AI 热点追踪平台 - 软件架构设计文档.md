## 1. 架构概述

### 1.1 项目背景

AI 热点追踪平台是一个面向 AI 时代的职业导航系统，致力于帮助用户了解 AI 最新动态、评估职业风险、获得学习指引、实现职业转型。

### 1.2 架构定位

| 维度 | 定位 |
|------|------|
| **架构风格** | 微服务架构（渐进式演进） |
| **设计方法** | 领域驱动设计（DDD） |
| **通信方式** | gRPC (内部) + HTTP/REST (对外) |
| **数据一致性** | 最终一致性 (事件驱动) |
| **部署模式** | 容器化部署 |
| **可用性目标** | 99.9%（生产级） |

### 1.3 架构愿景

构建一个**高可用、可扩展、易维护**的微服务架构，支持业务的快速迭代和持续增长。

## 4. 微服务设计

### 4.1 领域服务划分

基于 DDD 领域驱动设计方法，将系统划分为以下领域服务：

| 服务名称 | 领域职责 | 所属阶段 |
|---------|---------|---------|
| **user-svc** | 用户认证、信息管理、权限控制 | 第一期 |
| **content-svc** | 职业、学习路径、工具库、文章元数据管理 | 第一期 |
| **crawler-svc** | 内容抓取、清洗、AI 异步处理 | 第一期 |
| **search-svc** | 全文搜索、过滤排序、搜索建议 | 第二期 |
| **push-svc** | SSE 连接管理、实时消息推送 | 第二期 |
| **admin-svc** | 内容审核、数据统计、系统配置 | 第二期 |

### 4.2 服务间通信

```
┌─────────────────────────────────────────────────────────────────┐
│                    服务间通信机制                                │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  【同步通信】gRPC                                               │
│  • 适用场景：实时查询、强一致性要求                             │
│  • 通信方式：客户端直接调用服务端 gRPC 接口                       │
│  • 示例：网关 → 内容服务（获取文章详情）                        │
│                                                                 │
│  【异步通信】事件驱动                                           │
│  • 适用场景：状态变更、最终一致性场景                           │
│  • 通信方式：生产者发布事件 → 消息队列 → 消费者订阅处理         │
│  • 示例：采集完成 → 发布事件 → AI 服务消费 → 生成摘要            │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 4.3 API 网关职责

API 网关作为系统的统一入口，承担以下职责：

- **路由转发**：将请求路由到对应的微服务
- **认证鉴权**：验证 JWT Token，检查用户权限
- **限流熔断**：保护后端服务，防止过载
- **日志审计**：记录所有请求日志
- **协议转换**：HTTP/REST ↔ gRPC

## 5. 技术栈选型

### 5.1 完整技术栈清单

| 层级 | 技术选型 | 说明 |
|------|---------|------|
| **前端** | Vue 3 + Nuxt.js 3 | SSR 支持，SEO 友好 |
| **后端框架** | Go Zero | 内置微服务支持的 Go 框架 |
| **服务通信** | gRPC + Protobuf | 高性能 RPC 框架 |
| **服务发现** | Consul | 服务注册与发现 |
| **业务数据库** | MySQL 8.0 | 结构化数据存储 |
| **文档数据库** | MongoDB 7.0 | 非结构化文章内容存储 |
| **缓存** | Redis 7.0 | 热点数据缓存、会话存储 |
| **消息队列** | Redis Stream → Kafka | 事件驱动、异步解耦 |
| **监控** | Prometheus + Grafana | 指标采集和可视化 |
| **日志** | Loki + Fluentd | 日志聚合和查询 |
| **链路追踪** | Jaeger | 分布式链路追踪 |
| **容器化** | Docker + Docker Compose | 容器编排 |

### 5.2 关键技术决策

#### 决策 1：Go Zero 框架

**选择理由**：

- 内置微服务支持（服务发现、负载均衡、熔断）
- 完善的 gRPC 集成
- 代码生成工具提升开发效率
- 国产框架，中文文档完善

#### 决策 2：Consul 服务发现

**选择理由**：

- 专为服务发现设计
- 内置健康检查
- 支持多数据中心
- 单机→集群平滑演进

#### 决策 3：最终一致性模型

**选择理由**：

- 适合资讯类业务场景
- 通过事件驱动实现解耦
- 允许秒级延迟，用户体验可接受
- 避免分布式事务复杂度

#### 决策 4：渐进式存储演进

**策略**：

- **第一期**：单节点部署（简化部署，快速上线）
- **第二期**：主从复制、哨兵模式、副本集（高可用）
- **第三期**：分库分表、集群模式（规模化）

## 6. 基础设施架构

### 6.1 第一期：简化部署架构

**特点**：快速上线，简化运维，适合 MVP 验证

**部署清单**：

- 应用服务：Gateway × 2、content-svc × 2、crawler-svc × 1
- 数据存储：MySQL × 1、MongoDB × 1、Redis × 1（均为单节点）
- 服务治理：Consul × 1（单节点）、Prometheus + Grafana（基础监控）

### 6.2 第二期：高可用架构

**特点**：消除单点故障，达到 99.9% 可用性

**部署清单**：
- 应用服务：所有服务 ≥ 2 实例，Nginx 前置负载均衡
- 数据存储：
  - MySQL：主从复制 + 读写分离
  - Redis：哨兵模式（1 主 2 从 3 哨兵）
  - MongoDB：副本集（1 主 2 从）
- 消息队列：Kafka 集群（3 Broker）
- 服务治理：Consul 集群（3 节点）、Jaeger（链路追踪）、Loki（日志聚合）

## 8. 安全架构

### 8.1 认证授权模型

```
┌─────────────────────────────────────────────────────────────────┐
│                      认证授权流程                                │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  认证方式：JWT Token（无状态）                                  │
│  • 登录时颁发 Token（有效期 24 小时）                             │
│  • 包含用户 ID、角色列表、过期时间                              │
│  • 网关层统一验证 Token 有效性                                   │
│                                                                 │
│  授权模型：RBAC（基于角色的访问控制）                           │
│  • 预定义角色：admin、editor、viewer、crawler                   │
│  • 角色绑定权限（资源 + 操作）                                   │
│  • 用户分配角色，继承对应权限                                   │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 8.2 安全措施清单

| 安全领域 | 措施 |
|---------|------|
| **传输安全** | HTTPS 强制、CORS 白名单 |
| **输入验证** | 参数校验、防 SQL 注入、防 XSS |
| **速率限制** | 接口限流、防刷机制 |
| **数据加密** | 密码 bcrypt 加密、敏感数据加密存储 |
| **日志脱敏** | 敏感信息脱敏展示 |

```
│  验收：DAU > 10,000，可用性≥99.95%                              │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```
