# 爬虫抓取超时问题解决方案

## 问题描述

在抓取某些网站（如 Hugging Face）时出现超时错误：
```
context deadline exceeded (Client.Timeout exceeded while awaiting headers)
```

## 解决方案

### 1. 增加超时时间

对于响应较慢的网站，建议在 `crawler_sources` 表中设置更长的超时时间：

```sql
-- 示例：Hugging Face 配置
UPDATE crawler_sources 
SET timeout = 120,  -- 120秒
    max_retries = 5  -- 最多重试5次
WHERE name = 'Hugging Face Blog';
```

**推荐超时时间：**
- 国内网站：30-60 秒
- 国外普通网站：60-90 秒
- 响应较慢的网站（如 Hugging Face）：120-180 秒

### 2. 优化 HTTP 请求头

使用更真实的浏览器 User-Agent 和请求头，避免被反爬虫机制拦截：

```sql
UPDATE crawler_sources 
SET request_headers = JSON_OBJECT(
  'User-Agent', 'Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/120.0.0.0 Safari/537.36',
  'Accept', 'text/html,application/xhtml+xml,application/xml;q=0.9,image/webp,*/*;q=0.8',
  'Accept-Language', 'en-US,en;q=0.5',
  'Accept-Encoding', 'gzip, deflate, br',
  'Connection', 'keep-alive'
)
WHERE name = 'Your Site Name';
```

### 3. 代码层面的改进

已在 `scheduler.go` 中实现以下优化：

#### a) 智能重试机制
```go
// 指数退避重试策略
for attempt := 1; attempt <= maxRetries; attempt++ {
    resp, err = client.Do(req)
    if err == nil {
        return resp, nil
    }
    
    // 等待后重试（2s, 4s, 6s...）
    waitTime := time.Duration(attempt*2) * time.Second
    time.Sleep(waitTime)
}
```

#### b) HTTP 客户端优化
```go
client := &http.Client{
    Timeout: timeout,
    Transport: &http.Transport{
        MaxIdleConns:        100,  // 最大空闲连接数
        MaxIdleConnsPerHost: 10,   // 每个主机最大空闲连接
        IdleConnTimeout:     90 * time.Second,
        TLSClientConfig: &tls.Config{
            InsecureSkipVerify: false,  // 生产环境应验证证书
        },
    },
}
```

#### c) 更真实的请求头
```go
req.Header.Set("User-Agent", "Mozilla/5.0 (Windows NT 10.0; Win64; x64) ...")
req.Header.Set("Accept", "text/html,application/xhtml+xml,...")
req.Header.Set("Accept-Language", "en-US,en;q=0.5")
req.Header.Set("Connection", "keep-alive")
req.Header.Set("Upgrade-Insecure-Requests", "1")
```

### 5. 调试和监控

#### 查看抓取日志
```sql
-- 查看最近的抓取失败记录
SELECT 
    s.name,
    s.url,
    l.status,
    l.error_message,
    l.duration_ms,
    l.fetch_started_at
FROM crawler_fetch_logs l
JOIN crawler_sources s ON l.source_id = s.id
WHERE l.status = 'failed'
ORDER BY l.fetch_started_at DESC
LIMIT 20;
```

#### 查看抓取源状态
```sql
SELECT 
    id,
    name,
    url,
    status,
    timeout,
    max_retries,
    consecutive_failures,
    last_error_message,
    next_fetch_at
FROM crawler_sources
WHERE status = 'active'
ORDER BY priority DESC;
```

#### 暂停问题源
如果某个源持续失败，可以暂时暂停：
```sql
UPDATE crawler_sources 
SET status = 'paused',
    description = CONCAT(description, ' - 已暂停，需要调整配置')
WHERE name = 'Problematic Site';
```

### 6. 常见问题排查

| 问题 | 可能原因 | 解决方案 |
|------|----------|----------|
| context deadline exceeded | 超时时间太短 | 增加 `timeout` 值 |
| connection refused | 网站拒绝连接 | 检查防火墙/代理设置 |
| 403 Forbidden | 被反爬虫拦截 | 更换 User-Agent，添加更多请求头 |
| 429 Too Many Requests | 请求频率过高 | 增加 `fetch_interval` |
| SSL certificate error | 证书问题 | 检查 TLS 配置 |

### 7. 性能优化建议

1. **并发控制**：通过 `MaxConcurrency` 限制同时抓取的源数量
2. **请求间隔**：在 `processHTMLSource` 中添加 2 秒延迟
3. **批量处理**：每次最多抓取 10 篇文章
4. **优先级调度**：高优先级的源先抓取
